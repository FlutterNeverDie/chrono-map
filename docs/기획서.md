## 1. 프로젝트 개요

연도 게이지를 움직이면 그 시점에 전 세계 지역별로 무슨 일이 있었는지 지도 위에서 한눈에 보는 웹사이트를 만든다. 수익은 Google AdSense 광고로 낸다.

### 배경

- 세계사는 보통 국가·지역별로 따로 배워서 "같은 시기 다른 지역에선 무슨 일이?"를 알기 어렵다.
- 예: 1492년 콜럼버스 항해 때 조선은 성종, 오스만은 바예지드 2세 — 이런 동시대 비교가 이 서비스의 핵심 재미다.

### 목표

1. 연도 하나를 고르면 12개 지역의 주요 사건을 3초 안에 파악하게 한다.
2. 검색 유입이 잘 되는 구조(연도·사건별 개별 페이지)로 광고 수익 기반을 만든다.
3. 1인 또는 소규모 팀이 운영 가능한 정적 사이트 구조로 유지비를 최소화한다. (백엔드 없음)

### 타깃 사용자

| 사용자 | 니즈 | 주 유입 경로 |
| --- | --- | --- |
| 중·고등학생, 수험생 | 세계사·동아시아사 흐름 정리 | "1492년 세계 사건" 같은 검색 |
| 역사 덕후, 일반 성인 | 재미, 동시대 비교 | 커뮤니티·SNS 공유 |
| 교사, 강사 | 수업 자료로 화면 띄우기 | 직접 방문, 북마크 |

### 성공 지표 (출시 후 6개월, 가설값)

- 월 방문자 3만 명, 평균 체류 시간 2분 이상
- 세션당 페이지뷰 3 이상 (연도 이동이 페이지뷰로 잡히도록 설계)
- AdSense 승인 완료 및 RPM 추적 시작

## 2. 핵심 컨셉과 화면 구성

화면은 **연도 게이지(시간) × 세계지도(공간)** 두 축으로 구성한다. 게이지를 움직이면 지도 위 핀과 지역별 사건 카드가 그 연도 기준으로 바뀐다.

- 연도 게이지는 모든 화면에서 **하단 가로 한 줄**로 고정한다.
- 지도는 **화면 전체를 덮는 평면 세계지도(메르카토르)**. 나머지 UI는 지도 위에 떠 있다.
- **시점 8개**: 동아시아(기본), 중앙아시아, 서아시아, 동유럽, 서유럽, 북아메리카, 남아메리카, 오세아니아. 고르면 그 지역이 화면 가운데로 회전하고, 사건 목록이 **그 시점에서 중요한 순서**로 다시 정렬된다. 좌우로 끌면 지구를 돌리듯 끝없이 이어진다.
- **연도별 역사 국경**: 지도 위 나라 영역과 이름은 선택 연도 기준이다(예: 1206년 한반도 = 고려, 중국 = 금·남송·서하). 데이터는 Cliopatria(Seshat, CC BY 4.0, 기원전 3400년–2024년)를 연도별 스냅샷 222개로 잘라 정적 파일로 둔다.
- 테마는 **일반**(기본, 종이 세계지도 느낌: 하늘색 바다, 베이지 육지)과 **다크** 두 가지. 헤더 버튼으로 전환한다.
- **다국어 8개**: 한국어(기본) + 영어, 중국어, 스페인어, 힌디어, 아랍어, 프랑스어, 포르투갈어. 헤더의 테마 버튼 옆에서 고른다.
- 지역 단위(12개): 한국, 중국, 일본, 중앙아시아, 동남아시아, 인도, 중동, 유럽, 아프리카, 북아메리카, 남아메리카, 오세아니아.

## 4. 콘텐츠·데이터 설계

사건 하나 = JSON 객체 하나다. 큼지막한 사건만 넣으므로 서버 DB 없이 모든 데이터를 사이트에 정적으로 싣는다. 원본은 사람·AI가 편집하는 텍스트 파일이고, 빌드 때 앱용 JSON으로 변환된다.

| 원본 (`content/`) | 내용 | 변환 결과 |
| --- | --- | --- |
| `events/<지역>.txt` | 사건 (파일 이름 = 지역) | `src/data/generated/content.json` |
| `rankings/<시점>.txt` | 시점별 중요 사건 순서 (사건 id 목록) | 같은 파일 |
| `polity-names/<언어>.txt` | 지도 나라 이름 수정·보충 | `public/borders/names/*.json` |

### 사건 형식

```
@ imjin-war
when: 1592 ~ 1598          ← 기간 사건. 한 해면 "when: 1592", 기원전은 음수
coords: 129.04, 35.1
category: war
importance: 5
source: https://...
title.ko: 임진왜란
title.en: Imjin War
place.ko: 조선
summary.ko: 도요토미 히데요시가 조선을 침략해 7년간 전쟁이 이어졌다.
```

- 모든 사건은 `start`~`end` 기간으로 저장한다(한 해 사건은 start = end). 선택 연도가 기간 안이면 "진행 중"으로 표시한다.
- 텍스트는 `title / place / summary` × 8개 언어. 한국어 필수, 없는 언어는 영어 → 한국어 순으로 대체.
- 자세한 규칙은 `content/CLAUDE.md`.

### 시점별 정렬

1. `rankings/<시점>.txt`에 있는 사건이 먼저, 그 순서대로 (데이터는 나중에 채움).
2. 나머지는 점수 순: 시점에서 가까운 지역 + importance + 선택 연도와의 가까움 (`src/lib/ranking.ts`).

### 위키백과 연동

- 사건마다 영어 위키백과 문서를 하나 연결한다(`wikipedia: Imjin War`). `npm run wiki`가 Wikidata를 거쳐 8개 언어 위키백과 문서를 찾고, REST API(page/summary)로 제목·첫 문단·주소를 받아 `content/wikipedia.json`에 저장한다.
- 화면은 위키백과 첫 문단을 가공하지 않고 보여주고, 카드마다 문서 링크와 CC BY-SA 4.0을 표기한다. 무료·키 없음.
- 그 언어 문서가 없으면 직접 쓴 요약 → 영어 위키백과 순으로 대체한다.
- 표기 원칙: 대한민국 관련 영토·명칭은 대한민국 입장(독도, 동해), 그 밖의 분쟁은 각 언어 위키백과 표기(`content/CLAUDE.md`).

### 연도 단위

- 선택 단위는 기간: 기원전은 세기(기원전 3세기 = -300~-201), 서기는 10년(710년대 = 710~719). ◀ ▶는 한 기간씩.
- 현재 기간은 게이지 손잡이 위에 표시한다.

### 필드 규칙

| 필드 | 규칙 |
| --- | --- |
| start / end | 정수. 기원전은 음수(기원전 221년 = -221). 0년은 없다. 한 해 사건은 start = end |
| precision | year / decade / century — 고대 사건은 "약 기원전 3000년"처럼 표시 |
| region | 파일 이름으로 정해짐: korea, china, japan, central-asia, southeast-asia, india, middle-east, europe, africa, north-america, south-america, oceania |
| place | 사건 장소 표시명 (예: 바하마 제도) |
| category | war, politics, science, culture, religion, economy, exploration |
| importance | 1–5. 줌아웃 상태에서는 4 이상만 표시해 핀 과밀 방지 |

### 시대 정의 (`eras.json`)

고대(–476) · 중세(476–1453) · 근세(1453–1789) · 근대(1789–1945) · 현대(1945–). 서양사 기준이라는 한계를 페이지에 명시한다.

### 운영

초안은 AI로 생성하되, 연도·장소는 위키백과 등 출처와 대조해 사람이 검수한다. AdSense는 자동 생성된 저품질 콘텐츠를 반려 사유로 본다.

## 6. 수익화 — Google AdSense

광고는 콘텐츠를 가리지 않는 위치에만 둔다. 게이지 조작을 방해하는 광고는 체류 시간을 깎아 오히려 수익을 줄인다.

### 광고 배치

| 위치 | 형식 | 기기 | 비고 |
| --- | --- | --- | --- |
| 우측 사이드바 | 300x600 디스플레이 | 데스크톱 | 지도 옆 고정 |
| 사건 카드 목록 사이 | 인피드 광고 | 모바일 | 카드 5–6개마다 1개 |
| 사건 상세 본문 하단 | 디스플레이(반응형) | 공통 | |
| 화면 하단 | 앵커 광고 | 모바일 | 게이지와 겹치지 않게 게이지 위·아래 위치 조정 필요 |
| 연도/사건 정적 페이지 | 자동 광고 | 공통 | 승인 후 테스트 |

### 승인 준비 체크리스트

- [ ] 독자 도메인 연결 (`*.pages.dev`·`*.vercel.app` 같은 호스팅 서브도메인은 승인 불가)
- [ ] 직접 검수한 사건 상세 페이지 최소 30–50개 이상 공개
- [ ] 소개(About), 개인정보처리방침, 연락처 페이지
- [ ] `ads.txt`를 `public/`에 배치
- [ ] Google Search Console 등록, sitemap 제출
- [ ] 쿠키 동의 배너(CMP) — 유럽 트래픽 대비

### 구현 메모

- `next/script`로 AdSense 스크립트를 로드하고, 광고 슬롯은 `<AdSlot>` 클라이언트 컴포넌트로 감싼다.
- 게이지로 연도만 바뀌는 경우 페이지 이동이 아니므로, 연도 변경 시 URL을 `/year/[연도]`로 갱신해 페이지뷰를 잡을지 결정 필요 (8장 열린 질문).

## 7. 기술 스택과 아키텍처

React 기반 Next.js를 정적 빌드(`output: "export"`)로 쓰고, 백엔드·DB 없이 Cloudflare Pages에 HTML만 배포한다(Vercel 무료 플랜은 광고 등 상업적 사용 불가). 사건 데이터는 저장소 안 JSON 파일이고, 빌드 때 연도·사건 페이지가 미리 생성된다.

**왜 Vite SPA가 아니라 Next.js 정적 빌드인가:** SPA는 빈 HTML을 내려주어 검색 노출과 AdSense 심사(콘텐츠 부족 반려)에 불리하다. Next.js는 같은 React지만 `/year/1492` 같은 페이지를 완성된 HTML로 만들어 준다.

| 영역 | 선택 | 용도 |
| --- | --- | --- |
| 프레임워크 | Next.js 16 (App Router) + React 19 + TypeScript | 정적 페이지 생성 |
| 스타일 | Tailwind CSS 4 | 반응형 레이아웃 |
| 지도 | d3-geo, d3-zoom, d3-selection, topojson-client, world-atlas | SVG 세계지도 렌더·확대 |
| 시간 축 | d3-scale, @radix-ui/react-slider | 비선형 연도 눈금, 접근성 갖춘 슬라이더 |
| 상태 | zustand | 선택 연도·필터 전역 상태 |
| 애니메이션 | motion | 핀 등장·카드 전환 |
| 유틸 | clsx, prettier(+tailwind 플러그인) | 클래스 조합, 포맷팅 |
| 데이터 | `src/data/*.json` | 사건·시대 정의, 빌드 시 읽음 |
| 배포 | Cloudflare Pages (정적 호스팅, 무료 플랜 상업적 사용 가능) | GitHub push 시 자동 배포 |

### 구조

```
GitHub 저장소 ──push──▶ Cloudflare Pages 빌드 (next build → out/)
                              │
src/data/events.json ─────────┤  generateStaticParams로
src/data/eras.json   ─────────┘  /year/*, /event/* HTML 생성
                              ▼
                     정적 HTML/JS (CDN) ──▶ 사용자 브라우저
                                              │
                                              └─▶ AdSense 스크립트
```

### 현재 상태

- `~/Documents/GitHub/chronomap`에 프로젝트 생성, 위 라이브러리 설치 완료
- `next.config.ts`에 `output: "export"` 적용, `npm run build`로 `out/` 정적 빌드 성공 확인

### 제약

- API Route, Server Action, 이미지 최적화 서버, ISR은 쓰지 않는다 (정적 export에서 불가).
- 사용자 제보(F-17)는 Google Form 등 외부 도구로 처리한다.
